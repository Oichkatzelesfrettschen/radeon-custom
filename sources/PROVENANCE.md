# radeon register-header sources

Authoritative, machine-readable register headers vendored here so the harvester
and the DDX-vs-DKMS enrichment diff are reproducible offline.  Each file keeps
its upstream copyright and permission notice verbatim (MIT).

## radeon-unified-0.3-source.tar.xz

The unified DKMS source tarball, generated by
`scripts/build_radeon_unified_source_tarball.sh` from the RS480/CachyOS
prepatched snapshot.  Contains the kernel/DKMS `radeon_reg.h`: the register
reference compiled into the radeon DRM module on vostro1000.  This is the header
the harvester decodes by default and the one the RS480_ patches extend.

## xorg_ddx_radeon_reg.h

The X.Org `xf86-video-ati` `src/radeon_reg.h`, a machine-readable superset of
the legacy Radeon MMIO register space (Copyright 2000 ATI Technologies Inc. and
VA Linux Systems Inc., MIT).  It decodes more of the R300-family register set
than the kernel header, so cross-referencing it recovers real, sourced field
geometry for RS480-accessible registers without OCR-ing AMD PDFs.

- Source: https://gitlab.freedesktop.org/xorg/driver/xf86-video-ati (branch master),
  path `src/radeon_reg.h`.
- Fetched: 2026-06-09.
- sha256: 0b884c9debd36135ebae5c711fe99447c907d9176bc1d95f2fabe33b2b4c626b
- 5679 lines, 1630 `#define`s.

RS480 is an R300-derived IGP, so the header's `R300_*` and `R200_*` (R200
predates R300, inherited) field decodes apply.  `R500_*`/`AVIVO_*`/`R600_*`+
defines at colliding offsets are later silicon and are filtered out by
`scripts/diff_ddx_enrichment.py`.

Mesa's own `src/gallium/drivers/r300/r300_reg.h` is the third authoritative
source: the richest decode of the R300 3D-pipe registers (named enum values,
effect comments, R300-vs-R500 chip gating).  It lives in the mesa-26-gororoba
tree, and the harvester reads it in place with `--header`.
